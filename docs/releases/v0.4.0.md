# Shen-C 0.4.0 release checklist

1. Merge the compile-first implementation after its Linux Clang/GCC, macOS,
   sanitizer and Bifrost checks pass. Preserve the qualification receipts at
   `docs/evidence/native-tail-qualification-20261019/`.
2. Update implementation and Nix versions to 0.4.0 and correct the changelog
   to describe the default native backend and explicit diagnostic interpreter.
3. Build macOS 15 and Ubuntu 24.04 binary archives on arm64 and x86_64 using
   `.github/workflows/release-binaries.yml`. Every platform must pass runtime
   tests, relocated source compilation, dependency audits and the complete
   cold/cached pinned suite before its archive is eligible for publication.
4. Merge the release preparation after CI passes. Tag the resulting main
   commit, retain the build commits and CI identities in the release receipt,
   and attach the four archives, source archive, receipts and SHA256SUMS.
5. Download the published assets and compare their SHA-256 hashes. Verify the
   release tag is reachable from main and all published suite receipts pass.

Reproduce a package locally from a clean tracked checkout:

```sh
make CC=cc -j2 all test
python3 scripts/package-release.py
python3 scripts/test-release-package.py dist/shen-c-0.4.0-macos-arm64.tar.gz \
  --suite-output dist/qualification
```

The archives contain the embedded-kernel CLI and the complete source compiler
support files. Dynamic execution needs an available C17 compiler; source
application compilation also needs Python and Make. No compiler or native
cache is bundled. macOS archives are not notarized. Linux's minimum supported
glibc is the one recorded in each Ubuntu 24.04 build receipt. Qualification
on these runners does not establish performance acceptance against Boehm.
